### CPU 预算：生产门槛未通过

通过只读 Observability 查询，限定容量 Worker、指定时间段，再仅提取 CPU、wall time、状态，不公开请求网络元数据。51 条调用事件均 outcome=ok；15 次带历史夹具的备份 CPU 约 **64–89 ms**，完整校验 **35–43 ms**，清理 **2–6 ms**。成功响应不能覆盖预算不符：当前免费套餐的 HTTP/Cron 标示 CPU 预算为 **10 ms**；额外缓冲或开发传输的成功不能作为长期保证。[官方 CPU 限制](https://developers.cloudflare.com/workers/platform/limits/)

因此没有把 500 题保护常量或本轮 12 MiB 功能成功称为生产容量认证。当前生产图片总量约为本轮样本的 1/5.3，但不能线性外推其 CPU。每日两次全量复制的七天图片容量约为源图片量 ×14；按当前源约 33.2 MB，按合成样本约 176.2 MB，均未含 manifest/JSON、失败批次、临界轮换重叠或其他账户用量。存储不是本轮首要阻塞。

后续决定已确认：维持免费套餐，保留简单备份、失败通知与人工恢复，暂缓分片和高级自动化；不采用此前套餐升级建议。此决定没有消除上述 CPU 可靠性缺口，也不构成生产备份授权或生产恢复目标验收。当前范围见[维护方案](DEVELOPMENT.md#当前取舍--2026-10-18)。

## 健康失败到邮件的真实验证

更新私有恢复测试应用；另建无 D1 绑定、无公开入口的故障应用，模拟依赖缺失。localhost 桥仅使用固定合成身份，连接测试应用、测试 archive 和已确认邮件通道；通知状态单独保存，不覆盖常规 watchdog 状态。

最初 Node 测试漏掉了 Workers 不支持 `redirect: 'error'`：健康应用被误报并发送一次测试告警。新增 workerd 用例复现 false≠true，改为 `manual` 且继续拒绝全部非 200 响应后通过。没有忽略首次失败或把邮件接受请求当作送达。

修正后真实闭环为：200/依赖就绪 → 503/缺 DB → 200/恢复。故障邮件和恢复邮件均在 Gmail INBOX 核验，时间分别为 06:01:26 UTC 与 06:01:35 UTC；另有修正首次误报的恢复通知。公开文档不保存实际收件地址或邮件 ID。

## 发布窗口演练与权限

独立 `ai-mls-m4-build-lab` 没有 D1/R2、公开路由、Cron 或模型密钥。使用既有 Git 集成、M4 分支、固定测试配置路径；未创建新凭据。禁用自动构建后 API 确认 false，恢复后确认 true；分支推送产生成功构建 `ea0ecdc7-ef14-4916-99f0-8e48aa172bb6`，源码为 `caa91dbec76bcd4160fbfb2f80a192a81b6dd1b0`，只发布 inert lab Worker。

暂停实验触发器时，已有构建继续完成，证明暂停不等于取消在途发布。生产窗口必须先清空/等完队列，再核对当前版本。固定 commit_hash 的人工构建 API 请求因现有 connector 权限被拒绝，没有扩权；停用自动触发后，控制台重试同一 SHA 成功（构建 `3474751b-ec1b-4046-aa26-3e3a51871c87`）；这只能作为旧提交重试证据，不能代替尚未构建的新 merge SHA。M4 方案据此改为：暂停及清空队列 → 准备并读回仓库短命令/变量 → 恢复触发且核实没有意外构建 → 用户批准合并触发唯一 Builds。该方案变更与生产窗口均待用户确认。

| 操作 | 后续所需权限/批准 |
| --- | --- |
| 日常开发、检查、PR | GitHub 仓库权限；浏览器 CI 不持 Cloudflare 凭据；用户批准合并 |
| Builds 设置、触发与队列控制 | 有权操作 Builds 的既有人工控制台会话；当前只读 connector 不具备人工触发能力，M4-A 不扩权 |

| Access、迁移、恢复 | 仍逐项独立批准；当前测试恢复工具的空测试目标保护不放开 |
