## 已复现与待验证风险

**A：旧页面答案可以提交给已修改的题目。** 隔离 API 实验先确认 `1+1`、读取版本，再由另一页面改成 `2+2`，随后用旧版本、旧答案 `2` 提交，实际返回 200 并生成记录。`ReviewInput` 未接收预期版本，页面也未发送；服务端事务比较的是本次请求重新读取的版本，不能证明答题人看到该版本。原有提交 ID 去重可保留，但不能替代版本冲突校验。20 条既有 API 测试及这一特征实验通过；“通过”表示缺陷被复现，不表示已修复。

**B：同步切换题目时局部作答状态缺少身份绑定。** `Practice` 用 state 保存答案、答案展开、自评和提交 ID，只有提交后 reset；父组件刷新 reviews 时未以题目 ID/版本重置。隔离浏览器实验用两道合成题，在第一题输入答案并展开解析，再从另一个请求删除该题并同步，截图观察到新题仍保留旧答案。该风险来自多页操作或刷新，不是已观察到的真实学生事故。

**C：非 JSON 的成功响应缺少会话恢复路径。** API helper 在 JSON 解析失败后返回错误对象，却仅在 HTTP 非成功时抛错；刷新随后把缺少字段的对象写入状态。隔离浏览器注入 200 HTML 登录页后出现框架错误页。此实验验证防护缺口，不证明生产 Access 每次过期都返回相同响应。真实 401/403、跳转与输入保留应一起验收。

其余仅为源码风险或产品假设，未作故障复现：上传没有请求级幂等键，响应丢失后重传可能形成重复草稿；保存编辑未携带客户端版本；照片在压缩前检查 6 MiB 且仅支持 JPEG/PNG/WebP，真实手机大图和 HEIC 的阻力未测；复习后 refresh 吞掉失败，重试状态需核查。暂不据此扩展为异步队列或通用离线系统。

原始合成数据脚本、日志与截图仅保存在本机受限的 `.sites-runtime/student-audit/`，不含生产学生内容。API 实验使用内存 SQLite 与模拟身份/R2；浏览器实验使用本地 Wrangler 和模拟模型，不连接云端 D1/R2。临时断言先因定位方式及框架错误捕获方式失败，随后按截图修正实验断言重跑，两场景 × 手机/桌面 Chromium 共 4/4 复现通过；没有业务修复。

## 最小改进方案（前两项已批准实施，评测暂缓）

| 顺序 | 最小范围 | 验收条件 |
| --- | --- | --- |
| 1 · 作答一致性 | 复用已有 version，提交携带并校验所见版本；变更题目 ID/版本时清空作答与自评、重建提交 ID；编辑冲突同样显式处理。无需数据库重构 | 两题同步切换后答案/评分为空；旧版本提交返回冲突且不写复习记录；同一提交重试仍去重；现有 Again/隔离测试保持通过 |
| 2 · 失败可恢复 | 拒绝非 JSON/缺字段成功响应，明确处理认证失效；区分提交成功与列表刷新失败，未确认结果前保留提交 ID 与必要输入 | HTML/401/403/刷新失败均不崩溃、不显示假完成、不重复计次；重新登录后给出清楚的继续操作路径 |
| 3 · 识别小样本评测 | 在独立 Preview 使用获准的无个人信息图片，先人工独立标注 20–30 张印刷、手写、分数公式与几何照片；固定模型/提示词版本和调用预算 | 逐张记录关键字段是否正确、失败类别、耗时、重试和人工修订时间；报告分子/分母及代表失败，不将筛查小样本冒充产品规格的 100 图 ≥95% 验收 |
| 4 · 使用走查 | 先由维护者在真实手机用合成/获准材料完成拍照、核对、复习、隔日回来；正式学生观察须先通过独立上线验收 | 记录独立完成情况、卡点、修订负担与到期状态；仅针对重复出现的阻力做小改动，不以浏览器设备模拟代替真实设备 |

前两项宜形成一个范围明确的修复 PR，以有意义的失败用例先复现，再证明修复；真实集成按[PR 验收规则](PR_ACCEPTANCE.md)执行。修复与测试状态见末尾；表中真实模型评测和正式使用观察尚未执行。评测先查明识别的主要错误，再决定是否改提示词/模型；不预先重写业务、不接入大型分析平台。学习记录仍明确为自评，近期不引入自动判分、额外学习模型或仪表盘重构。

## 一致性与失败恢复修复 · 2026-10-18

用户批准前两项后，本轮修改根目录应用/API/测试，不修改生产配置、不合并 main、不开展真实模型评测。

- 问题列表返回已有 version；编辑与复习必须提供所见 expectedVersion。编辑以版本条件更新，旧版复习在写入前拒绝，事务仍校验版本。旧请求缺少版本返回 400，冲突返回 409；旧浏览器需刷新加载新版。既有提交 ID 重试仍先查已保存记录，避免成功响应丢失后重复计次。复用已有列，无数据库迁移。
