# M3：隔离备份、告警、恢复与有限回滚

2026-10-18 · **隔离试点验收通过，生产接入未执行**。结构化结果见[验收证据](evidence/m3-2026-10-18.json)。本轮没有修改业务代码、生产 Worker 设置/版本、生产 Builds 或 Access。Sites 冻结仍阻塞。用户另行批准的五条根域 Email Routing DNS 记录已启用；未购买套餐。

## 当前运行关系

```text
测试 Preview D1 / R2 → ai-mls-pilot-ops（每 12 小时）→ 私有配套 archive
                                      ↑
独立 ai-mls-pilot-watchdog（每小时）→ 校验恢复点 / 唯一邮件入口

archive → 全新空恢复 D1 / R2 → 私有恢复应用 → localhost 操作网关 → 手机浏览器
```

备份源是既有独立测试资源 `ai-mls-preview-db` / `ai-mls-preview-images`。新建 `ai-mls-m3-backups`、`ai-mls-m3-restore-db`、`ai-mls-m3-restored-images`，均与生产隔离；两个新 R2 桶的公开访问关闭。

三个测试 Worker 的 workers.dev 和版本预览 URL 均关闭，没有配置公开路由。恢复应用使用未修改的应用构建，仅绑定恢复 D1/R2，没有模型密钥或生产 Access 参数。合成身份仅由不部署的 localhost 网关注入；这项证据不包含生产 Access 或正式学生认证。

## 备份与告警契约

[backup.mjs](../ops/backup.mjs) 在一个 D1 batch 事务中读取三张业务表；新增业务表或列导致明确失败。此格式是当前 schema 的 JSON 数据快照，不是任意 D1 的通用 SQL 导出。恢复目标必须先使用同版迁移初始化；迁移账本不当作业务数据恢复。

图片按不可变引用复制到独立 archive，数据库和每张图片均做 SHA-256 读回校验，最后写 manifest 才形成恢复点。并发新上传进入下一点；缺图、并发删除或校验失败不能形成成功点。业务删除不传播到尚未过期的备份。

备份每 12 小时运行，恢复点满 11 小时即可续点，容忍任务启动抖动，避免严格 12 小时判断跳过整轮，给每日目标预留重试余量。七天保留按快照开始时间计算；过期点不再用于恢复，下一次清理删除其 manifest、对象和残留部分批次。不是七天内不可删除的 WORM 存储。

[watchdog.mjs](../ops/watchdog.mjs) 是独立 Worker：即使备份 Worker 不执行，也检查最后成功恢复点的年龄和可恢复性。阈值为超过 24 小时，最迟在下一次小时检查报告；不承诺瞬时告警。它不创建备份、不切版本、不自动恢复数据。两个 Worker 共用 archive，但分别保存去重状态。

唯一告警渠道是用户确认且 Cloudflare 已验证的邮箱，发件与收件均受绑定限制。已在 Gmail 收件箱核验通道测试、超龄告警、恢复通知三封邮件。公开证据不保存实际邮箱或邮件 ID。状态存储损坏仍尝试邮件；失败不记录发送成功；相同故障六小时提醒，恢复通知一次。邮件不包含题目、owner、图片 key 或原始错误。

最终审查发现严格十二小时判断会因启动抖动漏轮；先以“十二小时减一秒”用例复现失败，再修正续点阈值并完成回归。

本轮有效恢复点开始于 **05:03:51.062 UTC**，合成故障发现于 **05:03:57.279 UTC**，真正云端应用手机验收于 **05:11:22.266 UTC** 完成：

## 有限代码回滚

先在运维测试 Worker 验证 404 → 新版两次 500 → 操作者回滚 → 404；再在私有恢复应用的真实 `/api/progress` 验证 **200 → 新版两次 500 → 操作者回滚 → 手机浏览器再次通过**。

回滚前核实新版本就是注入故障的版本、没有较新发布、旧版兼容现有数据、运行配置和绑定一致。恢复应用的上传来源注释发生变化，不属于运行配置；其余设置逐项相同。回滚不回退 D1/R2；随后再次核验原图、历史和新复习持久化。回滚后再次通过手机验收，计时见结构化结果。原始日志、截图及运行元数据仅保存在本地受限证据中，不作为公开仓库附件发布。

六种不满足授权条件的策略用例均拒绝回滚。没有建设无人值守回滚。生产数据恢复、Access 变更和迁移仍需单独批准。

## 后续操作入口

- `pnpm test:recovery`：仅本地 Miniflare/workerd 合成数据，不需要云端凭据；已加入原有无部署权限的 GitHub 检查，不另建发布流水线。
- `node ops/prepare-config.mjs backup /absolute/private/backup.json` 与 `watchdog`：生成固定测试资源的私有 Wrangler 配置。必须先设置 `M3_ACCOUNT_ID`、`M3_SOURCE_DATABASE_ID`、`M3_PRODUCTION_DATABASE_ID`、`M3_ALERT_TO`、`M3_ALERT_FROM`。相同生产/测试 D1 ID、缺失或非法输入会被拒绝。生成器不能替代核对实际 ID 的资源归属。
- 检查配置中的 Worker 名、D1 ID、桶名、收件人和公开入口后，才用 `wrangler deploy --config /absolute/private/config.json`。当前稳定 Cron 是 `0 */12 * * *` 和 `15 * * * *`；临时每分钟触发器已撤下并由 API 复核。
- 恢复：先盘点故障和批准范围，保留原目标，创建同 schema 的空隔离 D1/R2，验证 manifest，再调用 `restoreBackup`，核验行、图片和应用行为后才讨论切换。部分失败的目标不能上线；不得把清空现有库作为恢复默认步骤。
- `tests/recovery/cloud-bridge.mjs` / `cloud-app-proxy.mjs` 只允许 localhost 操作者使用，**不能部署**。前者绑定测试源、测试 archive、恢复目标和测试邮件；后者只绑定无公开入口的恢复应用。所有实际 ID 从受限配置提供，公开仓库不保存凭据或实际收件地址。
- `pnpm test:recovery:browser`：操作者先启动 `127.0.0.1:8795` 私有应用网关，并确认合成题到期后运行。该命令不自动创建资源、登录或修改生产，也不属于普通 PR 的无人值守云端验收。

本轮 OAuth 仅 account:read、user:read、workers_scripts:write 和工具附带的 offline_access，凭据加密并由系统钥匙串保护。没有申请 D1/R2/Access/DNS API 写权限；但脚本写权限仍能通过 Worker 绑定访问数据，不能称为技术上仅能操作测试资源的权限。此次实际绑定均独立核验为测试资源。

## 尚未证明与生产前条件

当前真实样本只有两张小合成图片。500 张图片、较大数据库的 CPU、子请求、扫描和恢复预算尚未验证；全量算法必须在生产接入前验证实际规模，必要时再分批，不以此次小样本外推容量。十二小时自然轮换及七天自然保留需要持续观察；本轮用调度证据、真实存储操作和明确的时间故障注入验证路径。

本轮不涵盖账户丢失、Cloudflare 平台故障、不可变异地副本、正式学生上线、真实模型可用性或生产恢复。生产接入及唯一发布入口切换属于 M4，必须另行授权。Sites 实际资源关系仍未核清，冻结保持阻塞。
